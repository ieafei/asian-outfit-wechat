# 精简公众号交付

## 产物与内容归属

默认只有 `images/`、`公众号粘贴版.html`、`封面_整合图.jpg`、`sources.json`。无需独立文章预览、Markdown、TXT、说明、清单、来源副本、顺序副本、组图预览或 ZIP。旧文章的文件不自动删除；明确需要某个格式时再导出该格式。

粘贴页集中放推荐标题、折叠备选标题、正文、独立置顶评论、几句上传说明与折叠纯文字备用区。正文段落、小节标题与图注**一律居中**输出，小节标题使用本篇主题色。只维护一份正文 DOM：富文本直接复制正文段落，纯文字和备用区从这些段落自动提取，不把整篇正文重复写进多个文件或多份脚本常量。正文默认只有文字排版、插图提示和正式图注，不嵌实图、不再生成完整图文预览。

推荐标题、正文、评论分别复制。正文只有一个复制按钮；复制范围不含标题栏、备选标题、封面编辑区、评论与操作说明，正文中的整合拼图提示与正式描述属于复制范围。纯文字备用区可手动选择复制，无需第二个正文复制按钮或备用 TXT。

## 插图位置与图注

正文第一段是**导语**：2—3 句描述这一篇图文本身（穿搭风格、场景氛围、读者能带走什么），不出现博主人名、账号和平台。导语之后立即放整合拼图的提示行，不配图注、不写描述，再接其余开头段落或动作小节：

```text
【整合拼图：请在此上传 封面_整合图.jpg，上传后只删除本提示行】
```

这一行属于可复制正文，富文本、纯文字和备用区同步保留；上传后整行删除。整合拼图是封面占位，**不配图注**——不要在图下面再写「整合拼图 · …」。复用 `封面_整合图.jpg`，不新增另一张拼图，也不占用配图 01 起的独立照片编号。正文共包含 1 张整合拼图与 3—6 张已选独立照片的位置。

本地照片不能充当已上传公众号的在线图片。每张照片的位置用两个独立普通段落：

```text
【配图01：请在此上传 images/01_姿势名.jpg，上传后只删除本提示行】

手搭上墙面，肩线跟着沉下来，站姿就不僵了。
```

文件名与图注必须替换为本篇实际内容；上传后只删除第一段，第二段保留。第二段是写给读者的说明（动作＋效果），不带「配图01 · 」编号——编号只在这条会被删掉的上传提示里。提示不加边框、背景、内边距或固定高度。复制正文用扁平 `p`、`strong` 和简单内联样式，不复制图片框、本地 `file://` 地址、Base64 或临时外链。图片只存 `images` 内一套，按正文顺序编号。全文用 UTF-8，页面无需远程字体、JS 或图片。

## 复用生成器

确认照片后，将一次创作的文案写进临时工作区 `draft.json`；把已确认图片和逐张记录放进单篇目录 `images/` 及 `sources.json`，然后运行：

```text
python <本技能目录>/scripts/build_article.py --directory <单篇目录> --draft <临时 draft.json>
```

脚本依赖 Python 和 Pillow；用 `load_workspace_dependencies` 提供的运行时，不假定固定设备路径。每次调用无需把整个脚本读入上下文或重写模板。

## 临时草稿结构

```json
{
  "title": "推荐标题",
  "alternatives": ["备选一", "备选二"],
  "intro": ["导语段落", "其余开头段落"],
  "collage_caption": "根据已选照片概括穿搭与整体氛围",
  "accent": "#6f4a75",
  "sections": [{
    "heading": "01｜动作小标题",
    "before": ["动作讲解"],
    "photos": [{"file": "images/01_姿势名.jpg", "caption": "实际动作图注"}],
    "after": ["神态或构图补充"]
  }],
  "ending": ["自然结尾"],
  "comment": "包含来源与关注我的置顶评论草稿"
}
```

`intro` 的第一段是导语（描述本篇图文，不出现博主人名、账号和平台），至少要有一个非空正文段落；整合拼图固定插在导语之后，不等全部 `intro` 结束。`collage_caption` 是一句实际图片描述，省略时生成简短通用描述；它只写进 `sources.json` 的 `cover.caption` 作素材记录，**不渲染到正文**（整合拼图不配图注）。`accent` 是本篇小节标题的颜色（十六进制），由写稿人从本期照片取色后指定；生成器把亮度收敛到白底可读区间，并把最终值记进 `cover.accent`、来源记进 `accent_source`。省略 `accent` 时按"逐图投票"自动提取，容易受肤色和背景干扰，只作兜底。`intro`、`before`、`after`、`ending` 支持字符串或段落列表；照片可指定 `focus` 为归一化裁切焦点 `[x,y]`，只影响封面。`sections` 里的 `photos` 必须覆盖 `sources.json` 中已确认的全部 3—6 张照片，不重复、不漏。

同一文件的来源记录包含 `file`、`platform`、`creator` 及技能规定的其他来源字段；若记录了 `sha256` 和 `dimensions`，脚本会校验，对不上直接报错——这正是防止「确认后偷偷换图」的机制。来源未核实的字段保留原值，不由生成器猜测。

`sources.json` 支持旧的逐图数组，也支持精简结构：`common` 保存共用平台、博主、原帖、成年依据等，`images` 保存逐图差异；脚本输出精简结构并以 `cover` 记录封面尺寸、网格和焦点，避免相同来源重复写 3—6 遍。每张图片的有效来源为 `common` 与该 `images` 条目合并，图片字段优先。

脚本仅生成粘贴页和封面，给 `sources.json` 补正文顺序、上传路径、图注与封面布局信息。它不搜图、不替用户确认、不上传发布，也不清理既有文件。临时 `draft.json` 不是交付产物。没有合适运行环境时按相同清单手工制作，不额外生成替代格式全家桶。

## 适量验证

每篇核对实际照片、引用路径、顺序、图注、来源与封面格子，确认正文照片完整且封面不切脸、不拉伸。

复用未改的稳定模板时以本篇数据和生成结果检查为主。模板首次使用、复制代码变化或出现复制/布局问题时，才需要打开粘贴页实测：读取实际 `text/html` 和 `text/plain`，确认导语段之后紧跟整合拼图提示（提示后没有图注或描述）、后续独立照片提示及图注齐全且分段、顺序正确，正文未混入标题/备选/评论/说明。用 `present` 把粘贴页交给用户自己点击复制；页面内的剪贴板逻辑优先写 `text/html` 与 `text/plain`，再按能力回退，只凭 `execCommand` 返回成功或页面提示不足以证明内容正确。
